# Technology Description Output Contract

This contract applies to the main **Technology Description** document generated by rnd-forge for expert/client review.

## Final-form mode

The Technology Description represents the **target technology in its completed, coherent form**. It is not a project-status report, backlog, laboratory notebook, or implementation plan.

The generated document must:

- describe the technology, process, modules, controls, measurements and validation logic as an integrated working system;
- use present/perfect technical language appropriate for expert review;
- read as a final technical concept even when internal R&D work is still ongoing;
- keep internal uncertainty, missing inputs, experiment planning and implementation status outside the expert-facing document.

The generated document must not contain status language such as:

- TBD;
- “not yet determined”;
- “will be selected later”;
- “after enough data is collected”;
- “future work is required”;
- “we still need to test”;
- “data is currently missing”;
- repository/CI/model bootstrap status;
- a section listing missing data or unfinished implementation.

## Evidence boundary

Final-form presentation does **not** authorize fabrication.

The generator must never invent:

- experiments that were not supplied as evidence;
- numbers or performance values not supplied as accepted facts/targets;
- certifications or compliance results;
- numbers of tested variants;
- “best formulation showed X%” claims without source evidence;
- patents, standards, customers, competitors or market facts.

When a concrete number is unavailable, write a technically complete statement without pretending that a measurement occurred. Accepted target ranges may be used when they are explicitly provided as project requirements.

## Separation of documents

Internal project repositories may contain:

- open questions;
- experiment plans;
- uncertainty;
- incomplete evidence;
- TODOs;
- development status.

rnd-forge uses these as inputs but does not reproduce their incompleteness mechanically in the Technology Description.

If an unresolved issue is essential to the meaning and cannot be rendered truthfully in final form without fabrication, generation should flag it in a separate generation report/review note, **not inside the main Technology Description**.

## Authority

This is a repository-wide generator requirement and applies to all projects unless a project explicitly selects another document mode.
