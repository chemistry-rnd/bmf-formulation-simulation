# Промпт 01: Генерация первого черновика описания технологии

## Когда использовать

Начало работы над новым описанием технологии. На входе — сырые материалы (документы, презентации, заметки), на выходе — структурированный драфт.

## Промпт

```
Ты — технический писатель, специализирующийся на описании инновационных технологий для фондов и инвесторов. Твоя задача — создать структурированный черновик описания технологии на основе предоставленных материалов.

## Входные данные

**Название технологии:** {название}

**Область:** {отрасль, подотрасль}

**Целевая аудитория описания:** {фонд Сколково / инвестор / грантовая заявка / внутренний документ}

**Материалы:**
{вставьте сюда текст документов, результаты экспериментов, заметки — всё что есть}

[Опционально: **Специфические требования:** {например, "акцент на clean-label", "фокус на масштабируемость"}]

## Требования к черновику

1. **Структура** — используй следующие разделы:
   - Общее описание технологии (2-3 абзаца)
   - Модульная архитектура процесса (разбей на этапы/модули с кодами)
   - Номенклатура / классификация продуктов (если применимо)
   - KPI процесса и KPI продукта (разделить!)
   - Методика контроля (in-line и off-line)
   - Результаты НИОКР
   - Конкурентные преимущества
   - Риски

2. **Качество данных:**
   - Все числа — с единицами измерения
   - Диапазоны вместо точечных значений (min–max)
   - KPI разделены по осям/измерениям (напр. внешний вид отдельно от внутренней структуры)
   - Никаких "значительно улучшает" — только конкретика

3. **Формат:**
   - Сложные данные — в таблицах
   - Каждый модуль — отдельный подраздел
   - В конце — список "Требует уточнения" (что не удалось извлечь из материалов)

4. **Тон:** Научно-деловой, точный, без маркетинговых преувеличений.

Создай черновик описания технологии.
```

## Что проверить в результате

- [ ] Все разделы на месте
- [ ] Нет абстрактных утверждений без данных
- [ ] Модули/этапы процесса чётко разделены
- [ ] KPI процесса отделены от KPI продукта
- [ ] Список "Требует уточнения" в конце — это ваши следующие вопросы эксперту

## Паттерны из практики (VivaCrumb)

- Подавайте максимум сырых данных — модель лучше работает с конкретикой, чем с абстрактным заданием
- Если есть несколько групп продуктов — укажите это явно, иначе модель обобщит
- Модульная декомпозиция (коды модулей типа YUD, LAB, MAP) помогает структурировать и дальнейшую работу
