# Промпт 03: Доработка конкретного раздела

## Когда использовать

Один раздел требует глубокой проработки — нужно добавить числа, детализировать процесс, разделить по подкатегориям. Используется итеративно для каждого слабого раздела.

## Промпт

```
Ты — технический писатель. Задача — глубоко проработать один раздел описания технологии.

## Контекст (всё описание, для понимания)

{вставьте полное текущее описание — или ключевые разделы для контекста}

## Раздел для доработки

**Название раздела:** {например, "Модуль YUD — Управление тестом"}

**Текущая версия раздела:**
{вставьте текущий текст раздела}

## Дополнительные данные для этого раздела

{вставьте новые данные: результаты экспериментов, замечания, протоколы}

[Опционально: **Конкретная задача:** {например, "разделить KPI по мякишу и корке", "добавить min-max по батчам", "описать двухуровневый контроль"}]

## Требования к доработке

1. **Детализация:**
   - Каждый параметр — с числовым диапазоном (min–max), не точечное значение
   - Если есть подкатегории (группы продуктов, оси измерения) — разделить по ним
   - Метод измерения для каждого показателя

2. **Структура раздела:**
   - Цель / назначение модуля (1-2 предложения)
   - Входные параметры
   - Процесс (пошагово, с параметрами)
   - Выходные параметры / KPI
   - Критические точки контроля
   - Таблица показателей

3. **Консистентность:**
   - Числа не должны противоречить другим разделам
   - Терминология — такая же, как в остальном документе
   - Если появляются новые термины — дать определение

Выведи обновлённый раздел целиком. В конце — список вопросов, если для полной проработки не хватает данных.
```

## Что проверить в результате

- [ ] Все параметры с числовыми диапазонами
- [ ] Подкатегории разделены (если применимо)
- [ ] Методы измерения указаны
- [ ] Нет противоречий с другими разделами
- [ ] Список вопросов в конце — следующие шаги

## Паттерны из практики (VivaCrumb)

- Раздел лучше дорабатывать по одному, а не все сразу — модель даёт более глубокий результат
- Указание конкретной задачи ("разделить по осям", "добавить min-max") даёт лучший результат, чем "улучши раздел"
- Модульные коды (YUD, LAB, MAP, PAR, COOL) помогают однозначно идентифицировать разделы
- Принцип "двухуровневый контроль" (процесс + продукт) — часто ключ к тому, чтобы раздел стал убедительным
