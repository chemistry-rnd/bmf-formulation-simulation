# Принципы написания технологических описаний

> Извлечены из опыта работы над описанием VivaCrumb (хлебопечение, clean-label shelf-life). Применимы к любому технологическому описанию.

---

## 1. Модульная архитектура вместо монолитного описания

**Проблема:** Монолитное описание "наша технология делает X" — трудно оценить, проверить, доработать.

**Решение:** Разбить технологию на именованные модули с кодами.

**Пример (VivaCrumb):**
- **YUD** — Управление тестом (замес, ферментация, расстойка)
- **LAB** — Лабораторный контроль (методики, показатели)
- **MAP** — Модифицированная газовая среда (упаковка)
- **PAR** — Частичная выпечка (par-bake)
- **COOL** — Режим охлаждения

**Почему это работает:**
- Каждый модуль можно дорабатывать отдельно
- Эксперт может дать замечания к конкретному модулю
- AI лучше генерирует детали при фокусе на одном модуле
- Легко отслеживать полноту — если модуль пустой, это видно

## 2. Числовые диапазоны вместо абстракций

**Проблема:** "Значительно увеличивает срок годности" — не информативно и не проверяемо.

**Решение:** Min-max по батчам, с единицами измерения.

| Плохо | Хорошо |
|-------|--------|
| "Существенно увеличивает" | "С 72 ч до 192-240 ч (+167-233%)" |
| "Улучшает текстуру" | "Пористость мякиша 65-70% (vs 55-60% контроль)" |
| "Снижает потери" | "Потери влаги 2,1-2,8% за 5 сут (vs 4,5-5,2% контроль)" |
| "Оптимальная температура" | "28-32°C (оптимум 30°C)" |

**Правило:** Каждое утверждение о преимуществе = число + единица + метод измерения.

## 3. Разделение KPI по осям

**Проблема:** Агрегированные показатели скрывают реальную картину. "Качество хлеба улучшилось" — по каким параметрам?

**Решение:** Разделять KPI по осям/измерениям.

**Пример (хлебопечение):**
- **Мякиш:** пористость, влажность, упругость, кислотность
- **Корка:** цвет (L*a*b*), хрупкость, толщина, влагопроницаемость

**Пример (другие области):**
- Материалы: прочность на разрыв vs сжатие vs изгиб
- ПО: latency vs throughput vs error rate
- Химия: выход реакции vs чистота vs себестоимость

## 4. Двухуровневый контроль: процесс + продукт

**Проблема:** Описан только результат ("срок годности 10 дней"), но не как его достигают и контролируют.

**Решение:** Два уровня контроля.

### Контроль процесса (in-line)
- Что контролируете **во время** производства
- Параметры: температура, время, pH, влажность в камере
- Цель: предотвратить брак

### Контроль продукта (off-line)
- Что проверяете **после** производства
- Параметры: органолептика, микробиология, физико-химия
- Цель: подтвердить качество

**Пример:**
| Уровень | Параметр | Метод | Частота |
|---------|----------|-------|---------|
| Процесс | Температура расстойки | Датчик в камере | Непрерывно |
| Процесс | pH теста | pH-метр | Каждый батч |
| Продукт | Пористость мякиша | Анализ изображений | Каждый батч |
| Продукт | Микробиология (КМАФАнМ) | ГОСТ 10444.15 | 1 раз в смену |

## 5. Номенклатура и группировка

**Проблема:** Технология описана "в общем", но на практике для разных продуктов параметры отличаются.

**Решение:** Явно выделить группы и показать различия.

**Пример (VivaCrumb):**
- **Группа A** — пшеничный хлеб (батоны, булки) → aw 0.89-0.91, pH 5.0-5.3
- **Группа B** — ржано-пшеничный хлеб → aw 0.87-0.89, pH 4.5-4.8

**Зачем:** Эксперт сразу видит, что технология адаптирована под разные продукты, а не "one size fits all".

## 6. Итеративная работа с AI: паттерны

### 6.1 Подавайте максимум сырых данных

AI лучше работает с конкретикой. Вместо "опиши технологию хлебопечения" — дайте таблицы параметров, протоколы, замечания эксперта.

### 6.2 Один модуль за раз

Глубокая проработка одного раздела даёт лучший результат, чем поверхностная переработка всего документа.

### 6.3 Формулируйте задачу конкретно

| Расплывчато | Конкретно |
|-------------|-----------|
| "Улучши раздел" | "Раздели KPI по мякишу и корке" |
| "Добавь детали" | "Добавь min-max по 5 батчам" |
| "Сделай лучше" | "Добавь двухуровневый контроль: процесс + продукт" |

### 6.4 Замечания эксперта → промпт

Замечания эксперта — идеальный входной материал для промпта. AI хорошо извлекает конкретные правки из свободного текста.

### 6.5 Проверяйте каскадные изменения

Одно замечание (напр. "разделите мякиш и корку") может повлиять на:
- Таблицу KPI
- Раздел методики контроля
- Описание модуля
- Сводную таблицу результатов

## 7. Антипаттерны (чего избегать)

| Антипаттерн | Почему плохо | Как исправить |
|-------------|-------------|---------------|
| "Уникальная технология" | Голословно, не проверяемо | Конкретные отличия от аналогов с числами |
| "Широкий спектр применения" | Размывает фокус | Конкретные группы продуктов с параметрами |
| "Инновационный подход" | Пустая фраза | Описание механизма инновации |
| Точечные значения без разброса | Нереалистично | Min-max по батчам |
| "По результатам исследований" | Без ссылки — не подтверждение | Номер отчёта, дата, лаборатория |
| Монолитное описание | Трудно дорабатывать | Модульная структура |
