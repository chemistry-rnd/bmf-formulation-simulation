**Стек**: Cloud Run (Python/Node) + Firestore + Secret Manager + Firebase Hosting

## Архитектура

```
User → Chat UI (Firebase Hosting)
         ↓
    Cloud Run API (Router)
         ├── Tier 1: GPT-4o-mini (FAQ, простые вопросы)
         ├── Tier 2: Gemini 2.0 Flash (большой контекст)
         ├── Tier 3: Claude Code Session (сложные задачи)
         │     ├── Primary: WebSocket bridge → локальная машина
         │     └── Fallback: Vertex AI Claude API
         └── Vector Search: embeddings для knowledge base
```

### Routing Logic

```
1. Input → size check (>4000 tokens → trim or Gemini)
2. Input → keyword extraction (GPT-4o-mini: "дай 5 релевантных слов без сленга")
3. Keywords → vector search → context
4. Input + context → GPT-4o-mini → ответ
5. Validation (GPT-4o-mini): "ответ полный? нужен ли Claude?" → yes/no + confidence
6. Если нужен Claude:
   a. Проверить bridge → если online → Claude Code session
   b. Если offline → Vertex AI (Claude Sonnet)
   c. Если и Vertex fail → "Эксперт ответит в течение часа" + сохранить в Firestore
```

## О фонде (FAQ-контекст для бота)

### Кто мы
ScaleWithAI VC — инвестиционный фонд, который покупает компании с сильными продажами но неэффективными
операционными процессами, и кратно повышает выработку на человека через AI-обучение команд.

### Команда
Группа инженеров из России, работающих на стыке AI и бизнес-операций. Люди, которые одинаково
свободно разбираются в архитектуре AI-систем и в операционке производственных компаний — от
проектирования RAG-систем до анализа штатного расписания завода.

### Партнёры
**Евгений Протасенко** и **271 Capital Advisory** (London).
- 271 Capital — financial & strategic advisory for tech-компаний, выросла из 271.vc
- Евгений: МФТИ, CFA Level I, ACCA, Google Cloud certified
- Лектор AWS Startup Academy, ментор Constructor Knowledge
- Экспертиза: strategy, fundraising, fractional CFO, M&A

### Процесс сделки
1. **Скоринг** — оцениваем компанию по K1–K4 (можно за 1 день по открытым данным)
2. **Deep dive** — штатное расписание, финансы, AI-индекс (1–2 недели)
3. **Сделка** — покупка из банкротства, вход в капитал, management buyout. Ключевое: операционный контроль
4. **AI-обучение** — 2–6 недель, начиная с ролей с максимальным ROI (бэк-офис → продажи → аналитика)
5. **Масштабирование** — тиражирование модели на следующие активы
6. **Выход** — 3–5 лет: продажа стратегу, IPO или дивидендная модель

### Целевые параметры сделки
- **Размер компании**: 30–500 сотрудников
- **Выручка**: $1M–$50M
- **Доля «экранных» ролей**: ≥30% штата
- **Доля ФОТ в себестоимости**: >40%
- **Отрасли**: manufacturing с большим бэк-офисом, BPO, логистика, инжиниринг, рекрутинг, бухгалтерия, колл-центры, юр. бюро
- **НЕ берём**: чистое ПО, hardware/robotics, компании без «экранных» ролей

### Позиция по робототехнике
Мы видим и уважаем потенциал робототехники и промышленной автоматизации. Но это не наша зона
компетенций. Наш фокус — интеллектуальный капитал: обучение людей, не замена оборудования.
Если потенциал компании — в замене конвейера роботами, мы честно скажем: вам нужен другой
тип инвестора. Мы сильны там, где ценность создаётся людьми за экранами.

## Технические решения

### Chat UI
- Vanilla JS + CSS (без фреймворков, как лендинг)
- marked.js для MD→HTML
- SSE для стриминга
- localStorage для session_id

### Backend (Cloud Run)
- Python (FastAPI) или Node (Express)
- Выбор: **Python** — лучше для AI/ML интеграций, OpenAI SDK, embeddings
- Docker → Artifact Registry → Cloud Run

### Bridge (локальная машина)
- Node.js скрипт, запускается как daemon
- WebSocket подключение к Cloud Run relay
- Запускает `claude --dangerously-skip-permissions` с промптом
- Стримит stdout обратно через WS

### Output Format
- Всё в Markdown
- Frontend рендерит в styled HTML
- Таблицы, заголовки, списки, code blocks
- Для длинных отчётов — instant-publish ссылка
