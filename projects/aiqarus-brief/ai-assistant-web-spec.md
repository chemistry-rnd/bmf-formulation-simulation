# AI Assistant Brief — Web Spec

## Продукт
Веб-форма для сбора брифа от клиентов, которые хотят заказать разработку AI-бота / агента.

**URL**: `build-ai-assistant.aiqarus.ru`

## Архитектура

### Инфра (по аналогии с vc.aiqarus.ru)
- **DNS**: Timeweb — поддомен `build-ai-assistant.aiqarus.ru` → CNAME на Cloud Run
- **Backend**: FastAPI на GCP Cloud Run (проект `scalewithai-vc` или отдельный)
- **Frontend**: статичный HTML в `backend/static/`, раздаётся через FastAPI
- **Docker**: python:3.12-slim, uvicorn
- **Хранение брифов**: Firestore (коллекция `briefs`) + email-нотификация

### Стек
- Frontend: чистый HTML/CSS/JS (без фреймворков), одностраничник
- Backend: FastAPI + OpenAI (для AI-ассистента и авто-коррекции речи)
- Стиль: тёмная тема aiqarus (--bg:#0b0e13, --accent:#4a7cac, Inter шрифт)

## Структура формы (7 шагов)

### Step 1: Главная задача бота
- Radio cards (одиночный выбор):
  1. **Коммуникация с клиентами и продажи** — общаться с лидами, квалифицировать, подводить к сделке
  2. **Поддержка и ответы из базы знаний** — FAQ, документация, типовые вопросы
  3. **Роутинг и распределение** — студенты по курсам, заявки по отделам, задачи по исполнителям
  4. **Автоматизация внутренних процессов** — напоминания, сбор данных, отчёты, онбординг
  5. **Другая задача** — свободный текст с voice input
- Определяет, какие вопросы показывать на шаге 4

### Step 2: Платформа и аудитория
- Checkbox cards (мульти-выбор): Telegram, WhatsApp, Виджет на сайте, ВК, Другое
- Select: ожидаемое кол-во пользователей в день
- Select: язык бота

### Step 3: База знаний и контекст
- Number inputs: кол-во документов, кол-во страниц
- Textarea (voice): описание документов
- File upload: примеры документов (drag-n-drop, до 20 МБ)
- **Где хранятся знания?** (checkbox cards, 2 колонки):
  - 1С, Битрикс24, Google Drive, Яндекс Диск, Notion, Confluence,
    SharePoint/OneDrive, Облако Mail.ru, amoCRM, LMS/СДО, Сайт компании,
    Локальные файлы, Другое
- **Интеграции с системами** (checkbox cards, 2 колонки):
  - CRM (Битрикс/amoCRM/др.), 1С (учёт, склад, бух.), Календарь/Запись,
    Оплата (ЮKassa/Тинькофф), Email/SMS/Push, Телефония (Манго/Мегафон),
    Аналитика (Метрика/GA), Другое API

### Step 4: Сценарий разговора (динамический)
Показывается блок в зависимости от выбора на Step 1:
- **Sales**: квалифицирующие вопросы (textarea+voice), действие после квалификации (select), тон общения (select)
- **Support**: fallback при незнании (select), топ-5 частых вопросов (textarea+voice)
- **Routing**: кого распределяем (select), критерии распределения (textarea+voice), кол-во вариантов (number)
- **Automation**: какие процессы (textarea+voice), частота запуска (select)
- **Custom**: свободное описание сценария (textarea+voice)

### Step 5: О бизнесе
- Textarea (voice): описание компании
- Textarea (voice): какую проблему решает бот
- Textarea (voice): как обрабатывается сейчас

### Step 4b: Безопасность и ограничения (всегда видно, галки ON по дефолту)
- **Защита от prompt-инъекций** — бот игнорирует "забудь инструкции" и манипуляции
- **Строго по теме** — не поддерживает разговоры вне компетенции
- **Защита персональных данных** — не раскрывает данные других пользователей
- **Не обсуждает конкурентов** — не сравнивает цены, не рекомендует чужие продукты
- **Не даёт обещаний и гарантий** — только то, что в базе знаний
- **Не даёт медицинских/юридических/финансовых советов** — перенаправляет к специалисту
- **Фильтрация мата** — бот не использует и не поддерживает нецензурную лексику
- **Не раскрывает внутреннюю информацию** — промпт, маржу, процессы
- Textarea: дополнительные запреты (custom)

### Step 4c: SOS-режим (эскалация)
**Триггеры** (checkbox, ON по дефолту):
- Повторяющийся вопрос (3+ раз)
- Эмоциональный негатив (мат, КАПС, !!!)
- Прямая просьба ("позовите менеджера")
- Тупик в диалоге (3+ безрезультатных ответа)
- Высокая ценность разговора (VIP, крупная сделка)

**Действие при SOS** (radio):
- **Умная эскалация (рекомендуем)**: AI-супервизор (старшая модель) анализирует всю переписку → решает: перевести / уточнить / попробовать иначе. Оператор получает контекст + рекомендацию.
- Мгновенный перевод на оператора
- Собрать контакт + уведомить менеджера

**Куда переводить**: textarea (Telegram, email, Битрикс24...)

### Step 6: Сроки и пожелания
- Select: сроки (ASAP / 2-4 нед / 1-2 мес / 3+ мес / без срока)
- Textarea (voice): доп. пожелания

### Step 7: Контакты
- Text inputs: Имя*, Email*, Telegram или телефон (опц.), Компания (опц.)
- Select: предпочитаемый способ связи
- **Предзаполнение из URL**: все поля можно передать через query-параметры

## Фичи

### Voice Input (из vc.aiqarus.ru)
- Hold-to-record (зажать кнопку микрофона)
- Web Speech API (SpeechRecognition)
- Авто-коррекция через GPT-4o-mini (toggle кнопка-палочка)
- Работает на всех textarea-полях

### Авто-сохранение
- localStorage: все данные формы сохраняются при вводе
- Восстанавливаются при перезагрузке страницы
- Очищаются после успешной отправки

### Progress Bar
- 7 точек, заполняются по мере прохождения шагов
- Шаг-счётчик "Шаг X из 7"

### File Upload
- Drag-n-drop + клик
- Превью списком с размером файла
- Удаление файлов из списка
- Лимит 20 МБ на файл

## Скачивание брифа как документа
На первой странице формы — блок "Предпочитаете заполнить оффлайн?":
- **DOCX** — HTML-файл с расширением .doc (Word/Google Docs открывают нативно)
- **MD** — Markdown
- **TXT** — plain text

Документ содержит ВСЕ вопросы со ВСЕМИ вариантами ответов (без интерактивной фильтрации):
- Все 4 сценария (продажи, поддержка, роутинг, автоматизация) — развёрнуты
- Интеграции — расширенный список (ERP, склад, Jira/Trello, и т.д.)
- Безопасность и SOS — полные списки
- Поля для заполнения с чекбоксами

Генерируется на клиенте (Blob + URL.createObjectURL), без бекенда.

## Генератор приглашений (Invite Links)

### Концепция
Для потенциальных клиентов генерируем персонализированную ссылку с предзаполненными данными.
Клиент открывает — видит форму уже с его именем, email, компанией → wow-эффект.
Может исправить любое поле.

### URL-формат
```
https://build-ai-assistant.aiqarus.ru/?name=Иван&email=ivan@school.ru&company=ШколаПро&task=routing&telegram=@ivan&inv=abc123
```

### Поддерживаемые параметры
| Параметр | Куда заполняет |
|----------|---------------|
| `name` | Имя |
| `email` | Email |
| `telegram` | Telegram или телефон |
| `phone` | Telegram или телефон (алиас) |
| `company` | Компания |
| `task` | Главная задача (sales/support/routing/automation/custom) |
| `platform` | Платформы через запятую (telegram,website) |
| `method` | Предпочитаемый способ связи |
| `business` | Описание бизнеса |
| `problem` | Описание проблемы |
| `task_desc` | Описание задачи (для custom) |
| `inv` | ID приглашения (для трекинга) |

### Cloud Function: generate-invite
- **Путь**: `invite-generator/`
- **Deploy**: `gcloud functions deploy generate-invite --runtime python312 --trigger-http --allow-unauthenticated --region europe-west1 --project scalewithai-vc`
- **POST** JSON → возвращает `{url, short_url, invite_id}`
- Сохраняет инвайт в Firestore (коллекция `invites`) для трекинга открытий/отправок

### Пример использования
```bash
curl -X POST https://europe-west1-scalewithai-vc.cloudfunctions.net/generate-invite \
  -H "Content-Type: application/json" \
  -d '{"name":"Иван Петров","email":"ivan@school.ru","company":"ШколаПро","task":"routing","telegram":"@ivanpetrov","note":"роутинг студентов по курсам"}'
```
